EPP-GAS 的 ROR（Real-or-Random）形式化安全证明示例

编写日期： 2026-07-23
目的： 以你熟悉的 EPP-GAS 方案为实例，展示 ROR 模型从建模到证明的全过程
难度： 密码学初学友好——每一步都有”人话翻译”
参考格式： BCCG 论文的 ROR 证明结构（Section V-A）、PPCDA 的 Game Hopping 风格

第〇步：先搞清楚 ROR 在证明什么

ROR 的”一句话定义”

ROR（Real-or-Random）模型证明的是：攻击者无法区分”真实的会话密钥”和”一个随机数”。

如果你分不清真密钥和随机数，说明密钥保护得足够好——攻击者无法破解你的通信。

EPP-GAS 中哪一步涉及”会话密钥”？

我们要证明的就是这个 SK 是安全的。 ROR 模型的所有游戏、查询、概率计算都围绕”攻击者能不能猜出 SK”展开。

第一步：定义形式化安全模型

1.1 参与者集合

🧑‍🏫 人话翻译： 把 EPP-GAS 的复杂系统模型化简——ROR 模型只关心”直接参与密钥协商的两方”（PL 和 RA_B）。其他的（编队成员、其他 RA）的影响通过密码学假设（签名安全、门限安全）”打包”到概率里。

1.2 协议实例（Oracle）

🧑‍🏫 人话翻译： 就像”通话记录”——每次 PL 和 RA_B 之间的认证都是一次”通话”（协议运行），有通话对象、有通话ID、有加密密钥、有通话状态。

1.3 攻击者能力（查询 Oracle）

攻击者 A 可以发起以下查询来攻击协议：

查询 符号 输入 输出 含义
执行 Execute(Π_PLⁱ, Π_RAⁱ) 两个空闲的实例 协议执行过程中所有的公开消息 A 窃听了 PL 和 RA_B 之间的一次完整认证
发送 Send(Π_Pⁱ, m) 目标实例 + 伪造消息 实例收到 m 后的响应 A 可以冒充 PL 或 RA_B 发假消息
揭示 Reveal(Π_Pⁱ) 一个已完成的实例 sk_Pⁱ（会话密钥） A 获取了这次通信的密钥（如：攻破了终端设备）
腐化 Corrupt(P) 一个参与者 P 的长期私钥 A 控制了 PL 或 RA_B 的长期身份
测试 Test(Π_Pⁱ) 一个”新鲜”的已接受实例 真实 SK 或随机数 核心！ 挑战者抛硬币 b，b=1 给真密钥，b=0 给随机数

🧑‍🏫 人话翻译： 这些查询定义了攻击者的”超能力”——他可以窃听、伪造消息、偷看某些密钥、甚至控制某些节点。ROR 证明就是要说：即使攻击者有所有这些超能力，他还是分不清真正的 SK 和一个随机数。

第三步：安全性证明（6 个 Game 的 Game Hopping）

证明主线概述

🎮 Game 0：真实协议

🧑‍🏫 人话翻译： Game 0 什么也没改，就是真实世界。我们的目标是一步步修改游戏，直到最后攻击者的优势变成 0，同时证明每一步修改只会引入可忽略的误差。

🎮 Game 1：引入随机预言机

🧑‍🏫 人话翻译： 这一步没有任何安全损失。SHA-256 够好 → 和真随机函数无法区分。这一步的目的是为后面的证明铺路——因为我们可以”控制”随机预言机的输出。

🎮 Game 2：排除 Hash 碰撞

🧑‍🏫 人话翻译： 我们排除了一种理论上存在但现实中不可能的”作弊”方式——找到 Hash 碰撞。这个排除引入的误差小到可以忽略（比”地球上两个人有相同的指纹”的概率还小得多）。

🎮 Game 3：排除签名伪造

🧑‍🏫 人话翻译：

  • 这个游戏说：如果你在我的协议里伪造 PL 的签名，那你实际上是在帮我破解 Ed25519
  • 因为 Ed25519 是安全的 → 你伪造不了签名 → 你的假消息都会被拒绝
  • 这里的关键技巧叫 Reduction（规约）：把”攻破我的协议”规约到”攻破一个已知困难的数学问题”
  • 之所以叫”构造 B”：B 是一个”中间人”，把 Ed25519 挑战者给的难题”包装”成协议的样子，让 A 来”帮忙”解

🎮 Game 4：排除门限绕过

🧑‍🏫 人话翻译：

  • Shamir 门限的牛逼之处：它是信息论安全的（而 Ed25519 只是计算安全的）
  • “信息论安全” = 就算攻击者有无穷的计算能力，没有足够的份额也解不出秘密
  • “计算安全” = 攻击者理论上能破解（如果计算无穷），但现实中算不动
  • 所以 Game 4 的误差（1/q ≈ 10⁻⁷⁶）比 Game 3 的误差（2⁻¹²⁸ ≈ 10⁻³⁹）还要小得多得多

🎮 Game 5：核心——把 SK 替换为随机数

为什么 A 分不出 Game 4 和 Game 5 的区别？——DDHP 困难性

🧑‍🏫 人话翻译（最重要的一个 Game！）：

  • 这是整个证明的核心
  • 攻击者在 Game 4 和 Game 5 之间分不清，因为要分清就需要解决 DDHP（椭圆曲线上的一个公认困难问题）
  • 攻破 DDHP 需要 ≈ 2¹²⁸ 次运算 → 宇宙毁灭都算不完
  • 所以在 Game 5 中，A 面对的是完全的随机数 → 优势 = 0
  • Game 4 和 Game 5 的差距 = DDHP 的安全性 → 可忽略

2. 为什么有些论文不做 ROR

回顾我们之前的讨论，现在你有了具体的理解：

  • PPCDA 不做 ROR 是对的：它没有传统的 ECDH 密钥交换。它的”会话密钥”是通过 Paillier 同态加密传递的，安全模型更适合 IND-CPA + Game Hopping 而非 ROR
  • BCADS 不做 ROR 也是对的：它做的是消息签名（可验证性+不可否认性），不是密钥协商
  • LETA 不做 ROR 也是对的：它用的是格密码，安全模型是 Q-ROM 而非传统 ROR

3. 你设计新方案时的”安全检查清单”

练习建议： 拿这个模板，尝试给 RTRA 写一个 ROR 证明。RTRA 有 ECDH 密钥协商 + Schnorr 签名，结构几乎和 EPP-GAS 一样，只是把”Shamir 门限”换成”Geohash 位置绑定 + 声誉”。这是一个很好的练习——先模仿，再原创。
