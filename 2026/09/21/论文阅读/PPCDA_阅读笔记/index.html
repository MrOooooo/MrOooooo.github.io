论文信息： Nuo Xu, Zhiquan Liu, Jian Weng 等, “PPCDA: A Privacy-Preserving Cross-Domain Authentication Scheme for Vehicular Platoons”
期刊： IEEE Transactions on Dependable and Secure Computing (IEEE TDSC) — CCF-A 类期刊
年份： 2026 年 3 月
DOI： 10.1109/TDSC.2026.3678933
阅读日期： 2026-07-15

第一遍：5 分钟快速筛选

标题拆解

PPCDA: A Privacy-Preserving Cross-Domain Authentication Scheme for Vehicular Platoons

关键词 含义
Privacy-Preserving 保护车辆身份的隐私
Cross-Domain 跨不同管理域（如跨省、跨运营商）
Authentication 身份认证（不是加密、不是密钥协商，就是认证）
Vehicular Platoons 针对车辆队列，不是单个车辆

Abstract 三句话提炼

四大贡献

贡献1： 提出 PPCDA 方案，用 IBF + BGLS 聚合签名实现「身份合法性 + 消息完整性」双重认证，用 Paillier 同态加密保护身份隐私。

贡献2： 批量认证机制 — 多个车辆队列的跨域请求同时处理。

贡献3： 动态认证机制 — 车辆加入/离开队列，不需要全部重新认证。

贡献4： 理论和仿真证明方案更好。

Table I — 核心对比表

读这张表的技术： 找”只有 PPCDA 打勾”的行。这些就是论文的卖点：

  • 「支持多个车辆队列」→ 只有 PPCDA 有
  • 「动态认证」→ 只有 [17] 和 PPCDA 有，但 [17] 用了区块链（开销大）
  • 「不用区块链 + 跨域队列认证 + 动态」→ 三合一，只有 PPCDA

Conclusion + Future Work

结论： PPCDA 在大规模跨域场景下确实更高效。

未来工作（论文自己承认的不足）：

  1. 进一步降低计算和通信开销
  2. 融入多维度的隐私保护
  3. 考虑队列的合并和拆分（merging and splitting） ← 注意这一点！

✅ 第一遍判断：这篇论文值得精读，是你的核心参考文献。

1. 场景与问题

场景设定：
一辆卡车队列（比如 10 辆卡车组成的车队）从广东省开到福建省。广东的 TA（信任机构）和福建的 TA 是不同的管理域。当车队进入福建时，福建的 TA 需要认证这些车辆的身份，但又不应该知道每辆车的真实身份（隐私需求）。

系统中的四种实体：

4. 核心方案 — 五个阶段详解

Phase A：Setup（系统初始化）

谁做： RTA（根 TA）

关键理解： skp 是整个系统的安全核心——只有 RTA 能解密车辆真实身份。如果 skp 泄露，所有车辆的隐私都没了。

Phase B：Registration（车辆注册）

谁做： 车辆 Vj + RTA

关键理解： PID = Encp(BID, pkp) 是这个方案隐私保护的基石。因为 Paillier 是同态加密，攻击者看到的只是一个随机数，但 RTA 可以在需要追溯恶意车辆时解密。

Phase C：Platoon Formation（队列形成）

谁做： RTA（队列形成后做身份登记）

IBF 在这里的作用（这是理解本文的关键）：
IBF 就像一个”成员名册的加密版”。

  • 插入操作 = 把车辆 BID 加到对应位置
  • 删除操作 = 从对应位置减去 BID
  • 这个特性让动态认证成为可能！

5. 密码学工具箱（3 个核心工具）

工具 在方案中的作用 为什么选它
Paillier ①加密身份→生成伪名 ②同态性质→聚合伪名验证身份 加法同态：Enc(a)·Enc(b)=Enc(a+b)
IBF ①存储队列成员的 BID 集合 ②支持增删操作→动态认证 可增删元素，比普通布隆过滤器更灵活
BGLS ①PF 签名→PL 聚合→STA 验证 ②批量认证多个队列 多个签名可聚合为一个，配对运算验证

6. 安全性分析

7. 实验设置与结果

实验环境：

项目 配置
CPU AMD Ryzen 9 5900HS (8 核)
内存 16GB
系统 Windows 11 64 位
密码学库 JPBC (Java Pairing-Based Cryptography)
密码运算耗时基准 每个运算跑 10⁶ 次取平均

各密码操作的毫秒耗时（Table V）：

操作 符号 耗时(ms) 直观感受
双线性配对 Tbp 6.19 🔴 最贵！一次配对≈5000次哈希
乘法运算 Tmul 2.98 🟡 较贵
Paillier加密 Tpe 2.39 🟡 较贵
Paillier解密 Tpd 1.56 🟡 较贵
Paillier密文乘 Tpcm 0.012 🟢 很快（同态的优势）
指数运算 Te 0.007 🟢 很快
加法运算 Tadd 0.061 🟢 很快
哈希运算 Th 0.001 🟢 极快

核心发现： 双线性配对是最贵的操作。方案好坏的关键 = 用了多少次配对运算。PPCDA 通过聚合签名大幅减少了配对次数。

实验结果摘要：

  • 计算开销：平均减少 **56.4%**（vs CDA-VI, MDPA, EPP-GAS）
  • 通信开销：平均减少 8.8%
  • 批量认证 vs 逐一认证：随着队列数量增加，优势更明显

8. 局限性分析

# 局限性 为什么是问题 可能的改进方向
L1 仍依赖 RTA 作为单点信任 RTA 持有 Paillier 主密钥，如果 RTA 被攻破，所有隐私都没了 用门限密码学分散 RTA 权力，或引入区块链去中心化
L2 Paillier 加密开销较大 每辆车注册要用 Paillier（2.39ms），队列形成要解密所有伪名 用更轻量的同态加密方案
L3 配对运算仍是瓶颈 单次认证需要 3 次配对（3×6.19=18.57ms） 探索无配对的方案（如纯 ECC）
L4 假设 CSP 和 RSU 不共谋 现实中 CSP 和 RSU 可能是同一运营商，会共谋 加入共谋抵抗机制
L5 没有用形式化验证工具 只用游戏跳转做理论证明，没有用 ProVerif/Tamarin 用形式化工具补充验证
L6 多队列合并/拆分没做 论文自述”future work include platoon merging and splitting” 设计队列合并/拆分的认证协议
L7 没有考虑后量子安全 双线性配对和 Paillier 在量子计算机下都不安全 替换为格密码等后量子安全的原语
L8 实验仅在单机上用 JPBC 测密码运算 没有在真实网络仿真中测试端到端性能 在 Plexe 等仿真器中进行网络级实验
L9 通信模型过于简化 没有考虑无线信道的不稳定性、丢包、延迟等 在更真实的信道模型下评估

公式(3) → 签名的生成

读完这篇论文后你应该能回答的问题

  1. PPCDA 解决了什么问题？ → 车辆队列跨域时的身份认证，要高效、要保护隐私、要支持动态变化。
  2. PPCDA 的核心思路是什么？ → 三个工具的组合：Paillier（加密身份） + IBF（管理成员） + BGLS（聚合签名）。
  3. PPCDA 和之前方案最大的区别是什么？ → 它是第一个同时做到「不需要区块链、支持队列场景、支持批量、支持动态」的方案。
  4. PPCDA 的隐私保护是怎么实现的？ → 每个车辆的伪名 = Paillier加密(生物身份哈希)。攻击者看到的是密文，只有 RTA 能解密。
  5. PPCDA 的批量认证为什么比逐一认证快？ → 多个队列的签名可以聚合，减少配对运算次数。
  6. PPCDA 有什么不足？ → 有单点信任（RTA）、配对运算仍然昂贵、没做网络级仿真、不支持队列合并/拆分、不抗量子攻击。
  7. 如果你是 PPCDA 的作者，下一步会做什么？ → 论文自己说了：降低开销、多维度隐私、队列合并拆分。但你还可以做：去掉配对运算、加入形式化验证、加入 Plexe 仿真、替换为后量子密码。
