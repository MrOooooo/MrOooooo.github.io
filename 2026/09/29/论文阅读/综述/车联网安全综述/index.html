Security Challenges in Internet of Vehicles (IoV) for ITS: A Survey

一、车载自适应网络技术

1.VANETS体系结构

  • **OBU（车载单元）：**OBU是安装在车辆内的一种设备，用于与VANET中的其他OBU和RSU交换信息。
  • **RSU（路侧单元）：**RSU是安装在路边或特定位置(如十字路口或停车场)的计算设备。此外，RSU还可以与其他基础设施网络中的其他网络设备通信。
  • **AU（应用单元）：**安装在车辆内的一种设备，它使用OBU的通信功能访问提供商提供的应用程序。

2.VANET中的通信方法

  • vehicle-to-vehicle (V2V)

  • Vehicle-to-Infrastructure (V2I)

  • vehicle-to-everything (V2X)

当VANET发生事故或交通堵塞时，车辆立即向网络中的其他车辆发送警告信号，并建议替代路线。通过V2V通信，车辆向附近的车辆发送信息，同时使用V2I通信通知安装在道路固定位置的RSU

3.安全目标

可用性：该发消息时能发出去，不被堵塞；

保密性：位置、身份只有合法车能看；

认证：确认“对方是真车/真路侧”，不是黑客冒充；

完整性：消息中途没被改；

不可否认：发了就不能赖账

二、车载自组织网络中的攻击者和攻击

1.攻击者

作为一般规则，攻击者试图更改消息的内容或创建虚假消息以获取自己的利益。根据他们的行为和目标，他们被称为自私司机、恶意攻击者、恶作剧者、贪婪司机、业内人士等。

主动 vs 被动：主动攻击者会收消息、改消息或伪造新消息再发出去，目的是降性能或非法接入；被动攻击者不发不改，只窃听收集信息，最难发现。

内部 vs 外部：内部是已授权节点（合法车、RSU、拿证书的节点），懂网络、能拿全量信息，危害最大；外部没授权，先探测再打，能力受限。

恶意 vs 理性：恶意攻击者不图利益，只搞乱网络、发假消息；理性攻击者图个人利益，比如伪造拥堵给自己让路。

本地 vs 扩展：本地只打某几个节点/某段路/某个RSU；扩展打大区域，甚至多节点协同让整片网络降级。

2.攻击

1）打“可用性”：让车/路侧发不出、收不到、路由不通

对应安全目标：授权用户随时能通信。

  • DoS / DDoS：大量假消息占信道，让正常安全消息进不去；多源同时打就是DDoS。V2V、V2I都中招。
  • Jamming（干扰）：用同频强信号压住DSRC/802.11p信道，事故预警都发不出去，安全应用最怕这个。
  • Malware：通过OBU/RSU软件更新注入恶意程序，让终端异常、乱发或宕机。
  • Broadcast tampering（原文拼成 Boradcast tempering）：合法节点身份但插入假安全广播，比如假事故、假封路。
  • Blackhole（黑洞）：收到RREQ就回假RREP，号称自己到目的最近；源车把包给它后它全丢。典型路由可用性问题。
  • Grayhole（灰洞）：比黑洞“温和”，先装正常，再选择性丢部分包，更难检测。
  • Greedy behavior（贪心）：主要在MAC层抢带宽，自己多传、别人拥塞。
  • Spamming：海量垃圾消息占带宽、拖慢真实数据。

2）打“保密性”：偷身份、位置、通信内容

对应目标：只有授权节点能看。

  • Eavesdropping（原文 Easvedropping）：被动窃听，拿车辆ID、轨迹、司机信息，用于后续跟踪。
  • Traffic analysis：不读明文也收集“谁和谁通信、频率多少”，推拓扑和出行规律。
  • Man-in-the-middle（MITM）：中间拦车/中间人夹在V2V之间，可改可重发；既破保密也常破完整/认证。
  • Social：发欺诈/不道德消息分散司机注意力，间接泄信息。

3）打“真实性/认证”：让假车混进网络

对应目标：确认消息来自合法车/RSU。

  • Sybil：一个节点造多个身份，同时报“前方拥堵”，别的车以为是多车共识，改走别的路，攻击者可独享空路。
  • Tunneling（隧道）：多个恶意节点串通，把包收过来改完通过“隧道”送到另一个恶意点再广播，伪装邻居/远程节点。
  • GPS spoofing：发假GPS坐标，隐藏真实位置或伪造在某地；可用于假路况、假紧急车、规避定位。
  • Node impersonation：盗用合法车ID/证书信息，冒充别人发消息。
  • Free riding：在协作认证里白嫖别人认证贡献，自己不提供身份/签名资源，占好处不搞事。
  • Replay：截合法消息，延时重发（如旧的位置、旧的通行许可），混进当前决策。
  • Key/certificate replication（原文 Key/Certification reception）：复制车辆密钥/证书，让TA在事故追溯、注销时混乱。
  • Message tampering（认证+完整双重）：V2V/V2I消息被改，既冒充又改内容。

4）打“完整性”：消息内容被改

对应目标：传输中不被篡改。

  • Masquerading：用假身份装成别的车/应急车，伪造、改包、重放都算。
  • Replay（也可归完整）：重发已收消息制造误判。
  • Message tampering：直接改路况、车速、事故类型，让别车走错路。
  • Illusion：广播与现场不符的警告（假追尾、假施工），制造错觉。

5）打“不可否认性”

  • Repudiation：出事后攻击者赖账“这消息不是我发的”。如果没强签名/审计日志，TA很难追责

三、VANET的安全路由协议

有初始信任/有TA的场景（军事、协同专网）可用可信中心做认证和关键任务；大规模民用更常走“托管环境”——TA/CA 管密钥、证书、撤销。

无 tamper‑proof 硬件、无统一TA（如车载娱乐/开放V2X）时，单靠中心认证不够，需要节点自评估、信誉、合理性检查。

安全≠越重越好：加密保机密/认证/完整，但数字签名、证书校验会增加时延与开销；路由协议要在“安全强度↔投递率↔开销↔可扩展”之间折中。

安全路由的目标：发现“最安全路径”，主路径失效能换备用，保证多跳中转节点不篡改、不丢、不冒名。

1. 密码学类（Cryptography‑based）

用数字签名、对称密钥、证书、假名等做认证/完整/不可否认。

1）SEPPBR — Secure and Efficient Protocol for Position‑Based Routing

  • 机制：基于位置选路 + 数字签名；额外设计评估机制识别“收到路由数据后丢弃或篡改”的恶意节点。
  • 解决：位置路由中的认证、完整、不可否认；对抗改包/丢包型内部恶意节点。
  • 表2表现：PDR Good，开销 High，可扩展未填（“-”）。适合安全优先但节点不多的高速场景。

2）EMAP — Expedited Message Authentication Protocol

  • 机制：用 HMAC（对称密码）替代耗时的证书撤销列表 CRL 检查；仅向未撤销 OBU 共享HMAC密钥，并做概率化密钥分发/更新。
  • 解决：VANET消息高频认证瓶颈、CRL查询慢；主要保认证。
  • 表2：PDR Good，开销 High，可扩展 Very high。偏“大网认证基础设施”，但对称机制对内部仿冒、非抵赖弱于非对称。

3）AMLA — Anonymous Authentication with Multi‑Level Anonymity

  • 机制：基于身份签名；多级假名匿名、假名签发机制可小集合查重保证唯一、每个别名有短期有效期，减少公钥证书依赖。
  • 解决：认证+完整+不可否认同时保隐私/匿名。
  • 表2：PDR Average，开销 Low，可扩展 Average。适合对隐私要求高、但不追求极致投递率的场景。

4）S‑BRAVE — Secure Beacon‑less Routing Algorithm for Vehicular Environments

  • 机制：证书交换保证消息在中间节点传递的有效性与完整；用邻节点作“guard node”，当下一跳不转发时由护卫节点补发，抗选择性转发/黑洞类攻击。
  • 解决：无信标路由下的认证、完整，以及转发节点偷懒/恶意丢包。
  • 表2：PDR Good，开销 High，可扩展 Average。

密码类小结：SEPPBR/S‑BRAVE重完整与抗丢包，EMAP重大网认证效率，AMLA重匿名。共同缺点是纯密码对“内部已授权但后来变坏”的节点要靠持续审计；签名/证书开销高。

2.信任/信誉类（Trust‑based）

不主要靠证书，而靠行为评价、邻车反馈、物理合理性判断“这辆车说的话/走的路可不可信”。适合半开放、动态、RSU稀疏环境。

1）MHLVP — 非视距位置核验方向

  • 机制：当V2V直视通信被建筑遮挡时，用plausibility checks（位置/速度/周边传感器一致性）核验对端申报位置。
  • 覆盖：完整、可靠、可用、认证、匿名、保密（表2列得很宽）；PDR High，可扩展 High。
  • 用途：城市楼宇场景防GPS欺骗/位置谎报。

2）DAATM — Dynamic/Distributed Trust模型

  • 机制：动态分布式信任，监控车辆播报警告时的合作与诚实度，按多参数演化信任值，过滤自私/恶意车。
  • 覆盖：data trust；PDR High；可扩展 Average。偏“消息层信任”而非严格路由寻路。

3）TM‑AODV — Trust‑enhanced AODV

  • 机制：在AODV路由发现中检测sinkhole/黑洞类 hub，避免把它们选入路径；中断后通知源重算。
  • 覆盖：主要可用性；PDR High，开销 Average。经典“把信任嵌进AODV”的思路。

4）VSRP — Vehicle reputation/plausibility

  • 机制：基于名誉+合理性检查，抗数据聚合篡改、丢包、假事件；识别并隔离恶意节点。
  • 表2：认证+data trust，PDR Average，开销 Low，可扩展 High。轻量但投递率一般。

5）DRS — Reputation model

  • 机制：接收消息后向通信范围内其他车询问发送者可靠性；若消息经RSU转，则综合RSU与始发评价。
  • 覆盖：data trust；PDR High，可扩展 High。靠多车交叉评价降低单点误判。

6）EDTCP — Enhanced Distributed Trust Computing

  • 机制：按邻居消息真实性给信任值并持续更新；分层数据传播减少误播；目标找出“最大全可靠车辆集合”。
  • 覆盖：认证；PDR High，可扩展 High。适合高密度城市网。

7）CSRP‑TDA — Channel‑state routing + Trust‑based Distributed Auth

  • 机制：按OBU能量/信道状态选可靠车；TDA做车内/车际分布式认证；降OBU能耗与时延，提升碰撞识别/广播率。
  • 表2：PDR Good，可扩展 Average；安全列空白（原文表未填主要安全项）。偏“信道+信任”联合优化。

信任类小结：信誉（DAATM/VSRP/DRS/EDTCP）抗自私、Sybil、假消息；plausibility（MHLVP/TM‑AODV/CSRP‑TDA）抗GPS谎报、sinkhole、位置不一致。短板是冷启动（新车无信誉）、共谋刷信誉、大网信誉表开销。

3. 混合类（Hybrid）

密码提供硬认证/完整，信任或合理性提供动态抗内部恶意，通常兼顾QoS。

1）SPBR — Secure Position‑Based Routing

  • 机制：数字签名做逐跳+端到端认证/完整/不可否认，配合plausibility checks抑制假位置注入。
  • 表2：认证/完整/不可否认，PDR未填，开销 Low，可扩展 Good。适合位置路由且要低开销。

2）S‑AMCQ — Secure multi‑constraint ant‑colony QoS routing

  • 机制：蚁群优化算多约束QoS可行路径；对内部攻击者加plausibility checks，结合扩展时变图（E‑VoEG）。
  • 表2：认证/完整/不可否认，PDR High，开销 Low，可扩展 Average。适合同时要求时延/带宽/安全的城市多目标选路。

四、挑战

1）区块链与去中心化安全

  • 挑战：传统TA/CA集中发证，在大规模IoV里存在单点、跨域互信、证书撤销延迟；内部节点作恶后溯源难。
  • 对策方向：用区块链存车辆身份、证书状态、路由行为、事件证据，实现不可篡改审计；PoA/ PoW/ PoS/ 联盟链做入网授权与共识；智能合约自动执行黑名单、保险/责任判定。
  • 遗留问题：车载节点算力有限、出块时延与交通安全消息低时延冲突、跨链互操作、GDPR/匿名与可追溯矛盾。
  • 和你方向的关系：你用PoA做入网认证、区块链存证，正好接这一段；可指出“相比通用公链，PoA+轻节点更适合车端”。

2）MEC / 边缘计算

  • 挑战：把认证、入侵检测、路由决策下沉到RSU/边缘服务器，可减少云往返时延；但边缘节点本身可能被攻陷，且边缘间迁移、负载均衡会带来新信任边界。
  • 对策方向：边缘做本地威胁检测、匿名凭证发放、低时延安全路由；云—边—车分层，敏感数据本地处理保隐私。
  • 遗留问题：边缘节点信任评估、边缘失效切换、边缘与区块链/SDN协同。

3）5G/C-V2X 与新接入

  • 挑战：从DSRC/802.11p扩展到5G、C-V2X，信道更宽但攻击面更大；超低时延高可靠（URLLC）要求安全机制不能重；网络切片若隔离不当会跨切片的横向移动。
  • 对策方向：切片级安全策略、基于网络的认证与密钥派生、空口加密+上层轻量签名。
  • 遗留问题：异构接入统一身份、切换过程中的会话连续性与重放防护。

4）QoS 与资源约束

  • 挑战：安全机制（签名、信誉表、区块链广播）会增加时延、能耗、带宽；而IoV同时要保PDR、低延迟、高吞吐。
  • 对策方向：多约束路由（时延/带宽/信任/安全分数联合）、轻量密码（轻量对称、聚合签名、批验证）、自适应安全等级（事故消息强认证、娱乐消息弱认证）。
  • 和你方向关系：ItFO/多目标路由可归到这一支，作为“安全—QoS联合优化”而不是单纯最短路径。

5）隐私与可追溯的平衡

  • 挑战：开放信道下位置/轨迹可被eavesdropping与traffic analysis；但事故/违法又要TA能去匿名追责。
  • 对策方向：假名/动态假名、k-匿名、混合区、群签名/环签名、条件匿名（合规机构可解密）；结合区块链存假名轮换日志。
  • 遗留问题：假名更换频率与安全/隐私/可追溯三角权衡，Sybil利用假名体系的成本问题。

6）大规模动态拓扑与跨域

  • 挑战：车辆高速移动、城间/省间漫游、多运营商多OEM，信任域不统一；传统AODV类路由和单域CA难扩展。
  • 对策方向：SDN全局视图做域内/域间流控与安全策略下发；联邦/联盟区块链做跨域身份；信誉跨域迁移。
  • 和你方向关系：SDN控制器可补“信任类冷启动、混合类无全局视图”的短板，这是你在related work里打第5章混合协议缺口的落点。

7）AI/机器学习安全（部分综述会在此提）

  • 挑战：用ML做入侵检测、信任预测、异常消息识别，但对抗样本、数据投毒、模型逆向会反噬。
  • 对策方向：联邦学习保数据隐私、鲁棒特征、在线更新；与规则型密码/区块链互为兜底。
  • 若你论文涉联邦学习，可在此对接“FL+区块链防投毒、PoA限制参与方”。
